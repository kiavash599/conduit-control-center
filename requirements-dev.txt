# Linting
# SRS: NFR-M-01, CONTRIBUTING.md
# PINNED (not a range): `ruff check` has no repo config and uses ruff's default
# rule set, which newer ruff releases expand — an unpinned range let CI pull a
# newer ruff that flagged 544 pre-existing findings and turned the Lint job red
# while the validated toolchain (this exact version) stayed green. Pin so CI
# lints with the same ruff the release was qualified against; bump deliberately.
ruff==0.15.17

# Security audit — checks dependencies against known vulnerabilities
# SRS: SEC-DEP-01, Issue #2 (CI pipeline)
pip-audit>=2.7.0,<3.0.0

# IANA time-zone database for `zoneinfo` (dashboard display timezone, v0.3.22).
# DEV/TEST ONLY, and deliberately NOT in requirements.txt: Linux — the only
# supported runtime target — resolves zones from the system tz database in
# /usr/share/zoneinfo, so the 30-package runtime closure is unchanged. Windows
# has no system tz database, so without this the timezone tests would fail on
# the Owner's Windows invariant run while passing on Linux/CI.
tzdata>=2024.1

# Release-tooling dependency (ADR-0003 A5): standard PEP 440 semantics for Requires-Python at
# active-input generation, reuse-authz validation, and connected acquisition. Declared DIRECTLY
# here (not transitively) so the release/generation tooling on the Owner PC + CI + WSL always has
# it; the builder image gets it from requirements-build-backends.lock (packaging==26.2). It is
# deliberately NOT in the runtime requirements.txt, so the 30-package runtime closure is unchanged.
# If unavailable, release/reuse_authz import fails at startup (fail closed; no hand-written fallback).
packaging>=24,<27
