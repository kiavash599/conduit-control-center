## 1. Objective

Deliver the combined Epic 1 + Epic 2 acceptance unit — a root-owned, non-service-writable privilege boundary and an immutable, versioned, transactional runtime lifecycle — and prove, on both supported Raspberry Pi platforms, that the first-transition install **and its rollback** are safe on real hardware.

## 2. Scope delivered

### Epic 1 — privileged trust boundary
- Deployed code under `/opt/conduit-cc` is root-owned and non-service-writable; the broad recursive `chown -R` is removed; `rsync` normalizes ownership explicitly and a verification pass fails closed on any non-root/setuid object.
- Privileged updater state moved to a root-only `/var/lib/ccc-update` (0700); a minimal status document is published into a separate service-readable `/var/lib/ccc-status`.
- The `.env` contract is single, canonical, `0600`, regular-file-only, atomically written everywhere.
- Out-of-band publisher trust-anchor ceremony (`ccc-provision-trust-anchor`); a group/other-writable candidate anchor is refused fail-closed.

### Epic 2 — immutable versioned runtime + transactional lifecycle
- Immutable `.venvs/<runtime-id>` store with a single-hop selector symlink and a full activation gate; legacy conversion is write-ahead recorded and resumable; deletion is manifest-authorized, never name-authorized.
- Per-attempt write-ahead update/rollback transaction with ordered, resumable phases; first-transition bootstrap ceremony (`ccc-bootstrap.sh` + snapshot runner) that never executes the installed legacy updater.

### Fixed — first-transition rollback path (the v0.3.19 field correction)
The Epic 1+2 unit was first exercised end-to-end on the RPi2 field device, which exposed two rollback-path defects (and one input-staging fault) that stalled the rollback at `diagnostic_failure`:

1. **`_verify_store_ownership` false-positive.** The shell store validator used a raw `find … -perm /6022` that false-flags standard venv interpreter symlinks (always mode 0777 under lstat). It now delegates to a new symlink-aware `runtime_store.py::validate_store_shape` (exposed as `validate-store-shape` on both runtime CLIs), which also enforces the hardlink/type/set-id boundary the raw scan never checked.
2. **Rollback nginx re-apply (step 5f).** An inline `sed` left `<CF_HTTPS_PORT>`/`<CF_HTTPS_REDIRECT_SUFFIX>` unresolved and only warned on a failed `nginx -t`. It now calls the shared `ccc-apply-https-port apply` helper (same as the forward path), which renders every placeholder, backs up the prior site, tests, and restores on failure.
3. **Trust-anchor input staging (harness).** The originally transferred `allowed_signers` was group-writable (mode 0664) and correctly refused by `ccc-provision-trust-anchor`; device rehearsals stage the anchor at `0600`.

## 4. Security properties (unchanged from Epic design)

- Privilege boundary and immutable runtime lifecycle are one acceptance unit; a change to either half reopens the combined invariant gate.
- Verification precedes every privileged action; the publisher SSH Ed25519 identity, SSHSIG namespace, and out-of-band device trust anchor are unchanged.
- The corrected rollback strengthens (never weakens) the store gate: the shared Python validator is a strict superset of the raw `find` it replaces.
