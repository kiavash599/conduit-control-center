# CCC Backlog Register

**Purpose:** a single, contributor-facing register of **accepted** backlog items — work the project has agreed is worth doing but has deliberately postponed. It exposes what is coming, why, and its priority, without committing a schedule. Implementation of any item is separately gated (design → Change Proposal → validation).

**Scope:** accepted, not-yet-implemented items only. Delivered work lives in the CHANGELOG and `docs/PROJECT-STATUS.md`; forward feature planning lives in the roadmap; architecture decisions live in `docs/adr/`.

**Conventions:** items are `BL-NNNN`; status is one of *Accepted*, *In Design*, *In Progress*, *Done* (on completion the row is moved out to the CHANGELOG/closure). Priority: Critical / High / Medium / Low.

- **RESEARCH-ONLY (2026-07-25): per-country client blocking is NOT supported and is not an accepted item.** Investigated at Owner request (example: blocking clients from Myanmar). Findings: (a) **Conduit exposes no geographic control** — the CLI capability matrix (roadmap §3.2, categories A–E) covers Personal Mode, client limits, bandwidth, metrics and Ryve only; the entire write surface CCC can drive is `--max-common-clients`, `--max-personal-clients`, `--bandwidth`, and `InproxyReduced*` via `--set`. Region appears **solely as read-only metric labels** (`conduit_region_*{scope,region}`, matrix D12–D15). (b) **The proxy does not choose its clients** — Conduit runs in-proxy from `psiphon-tunnel-core`; the node announces availability to the Psiphon **broker**, which matches censored users to proxies upstream of the operator. (c) **Firewall filtering is impractical for Conduit** — `install.sh` (step 2x-h) records the field-confirmed finding that Conduit binds **dynamic, high-numbered UDP ports that change at runtime**, so per-port rules are ineffective; CCC deliberately adds **no inbound UDP rules** (flows are outbound-initiated with stateful return traffic). Third-party "country-only" firewall projects operate at the ipset/iptables layer, are external to Conduit, and are reported to break Psiphon's discovery/health checks (node goes "dark"). (d) **The data to act on does not exist in CCC** — regional analytics are aggregate-only by construction (no IP, session, or per-client fields; see `docs/closure/regional-analytics-closure.md`), and GeoIP attribution is approximate. **Disposition:** research-only; not accepted, not scheduled. Any future reconsideration requires upstream Conduit support as evidence. Note also that Conduit exists to relay traffic for users in censored regions; where the underlying concern is resource consumption rather than geography, the supported levers are max-clients, bandwidth limit, and reduced-mode scheduling — all already exposed in the CCC Config panel.
